Urban data formats and sources

What urban data looks like before it reaches Autark: vector and raster models, the formats they travel in (GeoJSON, WKT, GeoTIFF, OSM XML), and where to get them.

This page is mostly reading, with a few live cells that open the same sample files the next page loads into a database. Cells run in the page: press Run, edit the code, and run again. The Overpass cell in section 4 asks the public server and falls back to a recorded answer if it is unreachable.

1Vector data

Urban datasets that represent features such as parks, roads and buildings are usually in vector format. Vector data uses coordinates and geometry (points, lines, polygons) to describe complex structures.

The coordinates of a geometry depend on a coordinate system. Urban datasets use either a geodetic system (defined over the Earth's surface) or a projected one. With a geodetic system the coordinates are 2D (longitude, latitude) or 3D (longitude, latitude, elevation).

In the drawings below, the origin is the top-left corner of the drawing area. The first coordinate grows from left to right (red axis) and the second from top to bottom (green axis).

1.1 Point and MultiPoint

A Point is a single spatial coordinate, for example (80, 40). A MultiPoint is two or more points, for example (80, 40) and (40, 80).

1.2 LineString and MultiLineString

A LineString is a list of connected points, for example (80, 40) to (40, 80). A MultiLineString is several LineStrings, here the previous one plus (20, 20) to (20, 60).

1.3 Polygon and MultiPolygon

A Polygon is a closed sequence of connected points, for example (20, 20), (80, 40), (40, 80), (20, 60), (20, 20). A MultiPolygon is several polygons; here a second one is added with (85, 10), (120, 15), (100, 40).

1.4 GeometryCollection

A GeometryCollection mixes geometry types. This one has a LineString through (20, 20), (80, 40), (40, 80), a Point at (20, 60) and a Polygon with (85, 10), (120, 15), (100, 40).

2Raster data

The raster format describes space as a regular grid of cells, usually called pixels. Each pixel stores a value for the area it covers, such as elevation, temperature or land use. Where vector data describes features through points, lines and polygons, raster data describes a phenomenon as a grid of values over space.

A raster dataset is defined by its spatial structure and its cell values: the number of rows and columns, the size of each cell, the geographic location of the grid, and the coordinate system that places it in space.

Each cell holds one or more values. A single-band raster may store elevation; a multi-band raster may store several spectral bands of satellite imagery.

3Urban data formats

3.1 GeoJSON

GeoJSON is a JSON-based format for vector data. It can describe a geometry, a feature, or a collection of features, and by default uses the WGS 84 coordinate reference system.

Per the specification, a GeoJSON object may be a Geometry (a region of space), a Feature (a spatially bounded entity) or a FeatureCollection (a list of features). The geometry types are Point, LineString, Polygon, MultiPoint, MultiLineString, MultiPolygon and GeometryCollection.

A Feature has three members: type ("Feature"), properties (descriptive attributes such as names or categories) and geometry (the shape). A FeatureCollection has type "FeatureCollection" and a features array; the properties and geometry belong to each feature, not to the collection.

3.2 Well-known text (WKT)

Well-Known Text is a human-readable text format for geometry only; it carries no attributes. A WKT object is a geometry type keyword followed by coordinates in parentheses: a POINT has one coordinate pair, a LINESTRING a sequence of pairs, and a POLYGON one exterior ring and optionally interior rings (holes).

Because WKT has no properties, it is usually paired with a tabular format: attributes in CSV columns and the geometry in a dedicated WKT column. This is how many open data portals publish geometry.

3.3 GeoTIFF

GeoTIFF is a raster format based on TIFF that stores georeferenced rasters. A GeoTIFF has two parts: the raster values, a grid of pixels each holding one or more values, and the georeferencing metadata (coordinate reference system, spatial extent, pixel resolution) that relates those pixels to real-world coordinates.

4Urban data sources

4.1 OpenStreetMap

OpenStreetMap (OSM) is an open, collaboratively maintained source of vector data about natural and built environments, created by a global community and free to use and share. It is widely used in GIS, urban studies, navigation and spatial analysis.

OSM has three structures: nodes, ways and relations. A node is a single position, like a GeoJSON Point. A way is an ordered list of nodes and can be a line or an area, like a LineString or Polygon. A relation groups nodes, ways or other relations into a more complex entity. Every element has tags, key-value pairs that say what it is.

4.2 Open data portals

Cities and public agencies publish urban datasets through open data portals such as NYC Open Data: transportation, land use, buildings, public services, infrastructure, environment and demographic indicators.

Depending on the dataset the information may be vector or raster, and is commonly distributed as CSV with WKT columns or as GeoJSON. These portals are important sources because the data is structured, regularly updated and georeferenced.
