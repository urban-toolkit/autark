Geographical data visualization with Autark Map

Draw 2D and 3D urban layers with WebGPU straight from GeoJSON, with no tile server and no backend.

autk-map is the rendering module of Autark. This page goes from an empty canvas to an interactive map and covers the main things the module offers: layers, OpenStreetMap data, rasters, thematic color and picking. The module does not care where a GeoJSON FeatureCollection comes from. When you combine it with autk-db, autk-compute and autk-plot, every call you learn here stays the same; only the origin of the data changes.

WebGPU check

navigator.gpu is the entry point of the WebGPU API. When it is missing, the browser does not implement WebGPU and autk-map cannot run. navigator.gpu.requestAdapter() asks for an adapter, a handle to one physical GPU (or a software fallback). It can resolve to null even when the API exists, typically because hardware acceleration is off. The next step, adapter.requestDevice(), gives the device that allocates buffers and submits work; map.init() does that for you.

Every example on this page needs WebGPU: a recent Chrome, Edge or Safari. Cells share state through ctx; run them in order or use Run all above ▶▶.

Data

The examples use three datasets of Manhattan, bundled inside tutorial/data/: the neighborhood polygons, a CSV of noise complaints with latitude and longitude, and OpenStreetMap roads and buildings. Load the first two once; later cells reuse them.

autk-map expects projected coordinates in meters, not longitude/latitude degrees. The standalone examples below project both datasets to Web Mercator (EPSG:3857) with D3. All layers in a map must use the same coordinate system. Later examples load data through autk-db, which already projects it to the workspace CRS (EPSG:3395 by default); do not project those results again.

1The lifecycle of a map

Every autk-map program has the same five steps:

  1. Put a <canvas> on the page.
  2. new AutkMap(canvas) creates the map controller: renderer, camera, layer manager, events and a small built-in UI.
  3. await map.init() acquires the WebGPU device and sizes everything to the canvas.
  4. map.loadCollection(id, {collection}) turns a FeatureCollection into a GPU layer. Call it once per layer.
  5. map.draw() starts rendering. By default the map draws once and then only when something changes.

2Layers

A layer is a GeoJSON collection plus a type that tells the renderer how to draw it:

map.loadCollection(layerId, {collection, type, property, loadConfig})
  • layerId is a unique string. Every later update (style, thematic data, picking, removal) addresses the layer by this id.
  • collection is the FeatureCollection.
  • type is optional for plain vector data and is inferred from the geometry. Physical types are never inferred; you ask for them.
  • property is required for rasters and optional otherwise (Sections 4 and 5).
  • loadConfig holds geometry options applied while the mesh is built, such as buildingsZeroHeight.
TypeGeometryNotes

Stacking. Physical layers always stack in the order surface, parks, water, roads, buildings, no matter when you load them. Generic layers go on top of the physical ones, in the order you loaded them.

Origin. The first layer you load defines the shared scene origin, so load the layer that covers your study area first. The default camera operates at a meter scale; loading longitude/latitude degrees directly would make the geometry effectively invisible.

The cell below loads the neighborhoods first, so they frame the map, and stacks the noise events on top as a points layer. Open the layer menu in the top-left corner and toggle the two layers.

3Connecting OSM layers

Autark also supports OpenStreetMap natively. autk-db fetches the data for an area and builds the base layers of a city map: surface, parks, water, roads and buildings. Under the hood it queries the Overpass API and converts the answer into the feature-centric model, so every building, street or park becomes a feature of a FeatureCollection, exactly like the ones loaded from files. That is what makes the two sources interchangeable: the map does not care whether a collection came from OSM or from a file, and both are loaded with the same loadCollection() call.

The loop below is the usual pattern. getLayersMetadata() lists the layers in the database with their names and types, and each one goes to the map under that type.

The original notebook read a prepared OSM extract (lower_mnt.osm.pbf) that is not part of this repository. This cell asks the Overpass API for a bounding box around Battery Park City and the Financial District instead. If the public server is busy or unreachable, it uses the answers recorded in data/osm/ and works offline (add ?overpass=offline to the URL to skip the live server).

4Raster layers

Raster layers represent gridded data such as temperature or density. autk-map renders a raster layer from a FeatureCollection whose cell values are stored in feature properties, together with a property path that tells the renderer which band to read. GeoTIFF files can be loaded with autk-db, and so can the heatmaps it builds with buildHeatmap().

The example builds a heatmap of Manhattan noise events (count of events within 700 m of each grid cell) and renders it under the neighborhoods. Raster layers need type: "raster" and property: "band_1". updateColorMap() with a PERCENTILE domain trims the extremes so most cells map to a readable range of colors.

5Thematic data

Thematic rendering maps a feature attribute to color. The attribute does not have to live on the feature itself: autk-map treats any value reachable through a property path as thematic input. It can be an intrinsic attribute of the geometry, or urban data that has been projected onto the feature, for instance by a spatial join in autk-db or a computation in autk-compute.

The workflow has four steps:

  1. Load the layer with loadCollection().
  2. Configure the color map with updateColorMap().
  3. Point to the source property with updateThematic().
  4. Turn thematic display on with isColorMap in updateRenderInfo().

5.1 Categorical attributes

Categorical palettes assign one color per class; use them for labels such as road types. It helps to first fold the raw values into a small, ordered set of groups so the palette domain stays stable. Here the roads of the OSM base map are grouped into primary, secondary and other under properties.compute.highwayGroup, and the USER domain fixes the order of the classes.

5.2 Diverging attributes

Diverging palettes suit signed or centered quantities, or any attribute with a meaningful midpoint that separates two regimes. The PERCENTILE domain trims outliers so most of the distribution maps to a clear range of colors. Neighborhood properties in this file are strings, so the cell converts shape_area to a number first.

5.3 Spatial joins

A spatial join attaches an aggregate from a second table to each feature of a base layer. A common use is counting point events, such as noise complaints, inside a buffer around each polygon or line. The cell below joins the noise events to the OSM buildings of the area, counting events within 1000 m of each building. The result is stored under properties.sjoin.count.noise, a property path autk-map reads directly, so the buildings are colored by the number of nearby complaints.

6Interactions

autk-map exposes three complementary interaction mechanisms. They share the same render-info flags and the same event bus, so they can be combined in any order:

  • Picking: pointer-driven selection that emits events through map.events.on().
  • Programmatic highlight and skip: direct control over which components stand out (setHighlightedIds()) or are hidden (setSkippedIds()).
  • Layer visibility: show, hide or fully remove a layer (isSkip in updateRenderInfo(), removeLayer()).

Enable picking on a layer with isPick: true, then double-click a neighborhood. MapEvent.PICKING delivers {layerId, selection}, where selection holds indices into the original collection. The cell highlights the picked features and lists their names; use the buttons to hide or restore the picked ones. The same selection arrays are what autk-plot emits and consumes, which is how maps and charts are linked.

Base styles are also available from code: map.style.setPredefinedStyle("light") accepts default, light, google, apple, osm and poster, the same presets the s key cycles through.
